CRITICAL FINDINGS (5)
================================================================================

1. ENCODING CRASH - Issue #4
   Location: data_import.py line 468
   Severity: HIGH (Data Loss)
   Problem: TXT files with GBK/GB2312 encoding crash entire import
   Impact: Non-UTF-8 files fail completely (common in China)
   Risk: Users resort to manual conversion, losing import audit trail
   Fix Time: 15 minutes

2. DATE MISMATCH SILENT CHANGE - Issue #12
   Location: universal_import_service.py lines 747-766
   Severity: CRITICAL (Data Loss)
   Problem: File with wrong date silently changes to correct date, deletes old records
   Impact: Accidental data loss if filename incorrect
   Risk: No confirmation, no warning log, user sees success
   Example: Upload TTV for 2025-11-05 but file has 2025-11-04 data → 11-05 deleted
   Fix Time: 30 minutes

3. STOCK CODE VALIDATION INCOMPLETE - Issue #2 & #11
   Location: data_import.py lines 634-641, universal_import_service.py line 230
   Severity: HIGH (Data Corruption)
   Problem: Only validates length and digit format, not actual stock code ranges
   Impact: Invalid codes like "000000", "999999" accepted and stored
   Risk: Corrupts database with fake stocks
   Examples Passing Validation:
     - 000000 (all zeros)
     - 999999 (doesn't exist)
     - SH1 normalized to "1" (too short)
   Fix Time: 20 minutes

4. SILENT DATE PARSING FAILURES - Issue #1
   Location: data_import.py lines 480-490
   Severity: HIGH (Data Loss)
   Problem: If 50% of dates malformed, silently skips those lines with no warning
   Impact: User thinks 1000 records imported, actually only 500
   Risk: No indication anything went wrong
   Fix Time: 25 minutes

5. STRICT COLUMN COUNT REJECTION - Issue #8
   Location: universal_import_service.py line 91
   Severity: MEDIUM-HIGH (Rejection)
   Problem: Rejects TTV/EEE files with 4+ columns (e.g., with comments field)
   Impact: Valid TTV files fail import
   Risk: Users can't import standard format files
   Fix Time: 10 minutes
